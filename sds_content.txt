Executive Summary
NexusCommerce is an AI-driven e-commerce decision support system developed to address the operational challenges faced by small and medium-scale online sellers who currently rely on fragmented tools, manual spreadsheet analysis, and intuition-based decision-making for managing their businesses. The platform unifies six critical business functions into a single intelligent system: data integration and quality management, demand forecasting, inventory intelligence with supplier management, an Agentic AI conversational assistant, interactive dashboard and reporting, and pricing intelligence with profitability tracking.
The system accepts sales and inventory data through manual file uploads in CSV, JSON, and Excel formats and processes them through an automated pipeline of per-row validation, median-based imputation, IQR outlier detection, automatic deduplication using PostgreSQL unique constraints, and anomaly detection with severity classification. Every upload generates a quality report with a score from 0 to 100, maintains version history with safe rollback capability, and tracks data freshness to ensure all downstream analytics are built on reliable and current data.
At the core of the system is an XGBoost machine learning model that performs recursive day-by-day demand forecasting, generating product-level predictions for 7, 14, and 30-day horizons with 95% confidence intervals and feature importance explainability. The system supports a 3-tier model priority where seller-specific fine-tuned models take precedence over category base models and fallback models. Sellers can personalize the forecasting model to their own sales patterns through a single-click warm-start fine-tuning mechanism that runs as a non-blocking background task, and model performance is evaluated using MAE, RMSE, R², and a custom 0-100 accuracy score derived from MAPE.
The inventory intelligence module goes beyond static threshold alerts by using ML-based risk scoring that combines current stock levels, forecasted demand, sales velocity, and supplier lead times to assign risk levels, calculate exact order deadlines, recommend specific restock quantities with safety buffers, compare supplier options, and quantify the financial impact of stock risks in terms of estimated lost revenue and restock costs. An overall inventory health score provides a single metric summarizing the state of the entire product catalog.
The Agentic AI conversational assistant operates in two modes. In Query Mode, it uses Retrieval Augmented Generation and Model Context Protocol tools to answer business questions grounded in real data from the PostgreSQL database. In Action Mode, it enables sellers to execute real business operations such as placing supplier orders, sending restock alerts, and generating PDF reports through n8n workflow automation, all through natural language commands with explicit user confirmation before execution.
The pricing intelligence module shifts the focus from revenue to profitability by tracking cost prices, computing actual profit margins, and using ML to recommend optimal prices with plain-English reasoning, expected profit impact, and price elasticity modeling. All insights are presented through an interactive dashboard with real-time filtering, auto-refresh every 60 seconds, data freshness monitoring, critical anomaly alerts, and business health scoring.
The system is built on a modular three-tier architecture with Next.js and React for the frontend, Node.js with Express.js for the backend API server, Python with FastAPI for the ML server, and PostgreSQL as the centralized database. Security is enforced through JWT-based authentication, bcryptjs password hashing, role-based access control, server-side seller isolation, parameterized queries, and an immutable audit trail for all AI-executed actions.
NexusCommerce transforms the way e-commerce sellers manage their operations by replacing guesswork with data-driven intelligence and manual processes with AI-powered automation, while keeping the seller in full control of every business decision.

1.3 Problem Statement
E-commerce sellers operating on platforms such as Daraz, Shopify, and Amazon currently lack access to affordable, integrated, and intelligent tools for managing their business operations. Sellers spend significant time manually analyzing sales trends using spreadsheets, often making inventory decisions based on intuition rather than data, leading to frequent stockouts that result in lost revenue or overstocking that ties up working capital. Demand prediction is either non-existent or relies on simple averaging methods that fail to capture seasonal patterns, trends, and product-specific behaviors. Pricing decisions are made reactively without understanding actual profit margins, cost structures, or demand elasticity, meaning sellers often do not know which products are truly profitable versus which merely generate revenue. Inventory monitoring is typically limited to checking stock levels against static thresholds, without factoring in supplier lead times, forecasted demand, or the financial consequences of running out of stock. When sellers identify that a product needs restocking, the process of contacting suppliers, calculating order quantities, and placing orders is entirely manual. Furthermore, insights from sales data, inventory status, and pricing analytics exist in separate systems with no unified view, forcing sellers to context-switch between tools and mentally correlate information. There is no conversational interface that allows sellers to ask natural language questions about their business or execute actions like placing orders through simple commands.
1.4 Problem Solution
NexusCommerce solves these problems by providing an end-to-end intelligent platform that transforms raw sales data into actionable insights and automated business actions. The system accepts data uploads in CSV, JSON, and Excel formats and runs an automated pipeline of validation, cleaning, deduplication, anomaly detection, and quality scoring, ensuring that all downstream analytics are built on reliable data. Demand forecasting is handled by XGBoost machine learning models that use engineered temporal features (lag values, rolling means, seasonal indicators) and recursive day-by-day prediction, providing product-level forecasts for 7, 14, and 30-day horizons with 95% confidence intervals and feature importance explainability. Sellers can further improve accuracy by fine-tuning models on their own store data through a warm-start training mechanism. Inventory management goes beyond static thresholds by using ML-based risk scoring that combines current stock, forecasted demand, and supplier lead times to assign risk levels (Critical, High, Medium, Low), calculate exact order deadlines, and recommend specific restock quantities with financial impact estimates. The Agentic AI assistant allows sellers to interact with all system data through natural language, asking questions like "Which products will run out this week?" and receiving data-grounded answers, or issuing commands like "Order 200 units of Product A" which the system confirms and executes through n8n workflow automation. The pricing module replaces guesswork with ML-based recommendations that factor in cost prices, demand forecasts, and profit margins, ensuring every pricing suggestion comes with plain-English reasoning and expected revenue impact. All insights are presented through an interactive dashboard with real-time filtering, role-based views, business health scoring, and model performance metrics.

1.6 Scope
NexusCommerce is a web-based AI-driven decision support system that provides e-commerce sellers with integrated tools for data management, demand forecasting, inventory optimization, pricing intelligence, AI-powered business assistance, and interactive reporting. The system accepts sales and inventory data through manual file uploads in CSV, JSON, and Excel formats and processes them through an automated pipeline of per-row validation, median-based imputation, IQR outlier detection, deduplication using unique database constraints, and anomaly detection with severity classification. Every upload generates a quality report with a score from 0 to 100, maintains version history, and tracks data freshness. The demand forecasting module uses XGBoost Regressor with recursive day-by-day prediction, supporting a 3-tier model priority of seller fine-tuned, category base, and fallback models, generating product-level forecasts for 7, 14, and 30-day horizons with 95% confidence intervals and feature importance explainability. The inventory intelligence module monitors stock levels and assigns ML-based risk scores combining current stock, forecasted demand, sales velocity, and supplier lead times, calculating exact order deadlines and recommending specific restock quantities with financial impact analysis. The supplier management component allows sellers to maintain supplier profiles with cost, lead time, and minimum order information. The Agentic AI conversational assistant operates in Query Mode (using RAG and MCP tools to answer questions grounded in business data) and Action Mode (executing supplier orders, sending alerts, and generating reports through n8n workflows with explicit user confirmation). The pricing intelligence module tracks product cost prices, calculates profit margins, and uses ML to recommend optimal prices with reasoning and expected profit impact. The dashboard provides interactive visualizations with real-time filtering, role-based views, business health scoring, and model comparison metrics. The system uses Next.js with React for the frontend, Node.js with Express.js for the backend API, Python with FastAPI for the ML server, and PostgreSQL as the centralized database. The system is designed as a prototype-level academic project for demonstration purposes.
1.6.1 Limitations/Constraints
LI-1: Data ingestion is limited to manual file uploads in CSV, JSON, and Excel formats. Automated scheduled data pulls from external e-commerce platform APIs are not supported.
LI-2: The demand forecasting module requires a minimum of 30 days of historical sales data per product. Products with insufficient data cannot be forecasted.
LI-3: Model fine-tuning runs as a background task taking 2-3 minutes and only one fine-tuning job can run per seller at a time. Stuck jobs auto-expire after 30 minutes.
LI-4: The AI conversational assistant depends on external LLM API availability. If the API is down, the assistant becomes unavailable.
LI-5: Workflow automation through n8n depends on webhook availability. If n8n is unreachable, action execution fails gracefully with error logging.
LI-6: The system is designed for small to medium-scale datasets and is not optimized for enterprise-level scalability or high-concurrency production deployment.
LI-7: All AI-triggered business actions (supplier orders, report generation) require explicit user confirmation before execution. No fully autonomous decisions are made.
LI-8: Real-time competitor pricing data, market scraping, customer behavior analysis, churn prediction, and marketing automation are out of scope.

1.8 Related System Analysis / Literature Review
1.8.1 Literature Review
Previous research in e-commerce demand forecasting and inventory optimization has demonstrated the effectiveness of machine learning approaches over traditional statistical methods. Makridakis et al. (2018) in their evaluation of ML methods for forecasting concluded that gradient boosting methods such as XGBoost consistently outperform classical approaches on structured business data, particularly when combined with engineered temporal features like lag values and rolling averages. However, most existing studies focus on aggregate-level forecasting and do not address the need for seller-specific model personalization, where individual business patterns differ significantly from general market trends.
In the domain of intelligent inventory management, Syntetos et al. (2016) highlighted that integrating demand forecasts with supplier lead time information dramatically reduces stockout rates, yet most commercial inventory tools still rely on static reorder point thresholds without considering forecast-driven risk scoring. The concept of Agentic AI, where conversational assistants move beyond passive question-answering to actively executing business actions, has gained attention through recent advances in Retrieval Augmented Generation (RAG) and tool-use frameworks (Lewis et al., 2020; Schick et al., 2023). While RAG-based systems have shown strong performance in grounding LLM responses in factual data, their application in e-commerce decision support with integrated workflow automation (such as placing supplier orders through natural language commands) remains largely unexplored. Our project addresses this gap by combining XGBoost-based forecasting with seller-specific fine-tuning, ML-driven inventory risk scoring with financial impact quantification, and an Agentic AI assistant that bridges the gap between analytical insights and executable business actions through n8n workflow integration.

1.10 Project Contribution
NexusCommerce introduces several technical and conceptual contributions compared to existing e-commerce analytics tools and decision support systems:
Seller-Personalized Demand Forecasting: Unlike generic forecasting tools that apply one-size-fits-all models, NexusCommerce implements a 3-tier model priority system where seller-specific fine-tuned XGBoost models take precedence over category base models and fallback models. The warm-start fine-tuning mechanism allows sellers to personalize predictions to their own sales patterns without requiring ML expertise, achieved through a single-click training workflow that runs as a non-blocking background task. This is the project's primary research contribution, investigating whether personalized fine-tuning measurably improves forecast accuracy over generic models.
Comprehensive Data Quality Pipeline: The system introduces a multi-layered data quality assurance pipeline that goes far beyond simple file upload. Every upload passes through per-row validation with 7 distinct rules and severity-based classification (critical/warning/info), median-based imputation, IQR outlier detection, and automatic deduplication using PostgreSQL unique constraints. The pipeline generates quality scores, maintains complete version history with safe rollback (requiring typed "ROLLBACK" confirmation), tracks data freshness with degrading scores, and stores every anomaly for later review and resolution. This level of data quality transparency is absent from commercial e-commerce tools.
Agentic AI with Real Action Execution: The conversational assistant goes beyond passive question-answering by implementing an Agentic AI architecture with two distinct modes. Query Mode uses Retrieval Augmented Generation (RAG) and Model Context Protocol (MCP) tools to ensure every answer is grounded in the seller's actual business data from PostgreSQL, never relying on general LLM knowledge when real data exists. Action Mode transforms the assistant into an agent that can execute real business operations (placing supplier orders, sending restock alerts, generating and emailing PDF reports) through n8n workflow automation with explicit user confirmation and double confirmation for high-value transactions. This integration of conversational AI with workflow execution represents a novel application in e-commerce decision support.
Financial Impact Quantification in Inventory Management: Rather than simply flagging low stock with color-coded alerts, the system quantifies every inventory risk in financial terms, showing sellers the estimated revenue they will lose from a stockout and the cost of the recommended restock order. This transforms abstract risk levels into concrete business decisions.
Profitability-First Pricing Intelligence: The pricing module shifts the focus from revenue to profitability by requiring cost price inputs and computing actual profit margins before generating recommendations. Every ML-based price suggestion enforces a minimum 15% margin constraint, never recommends below cost price, and includes plain-English reasoning with expected profit impact, ensuring sellers understand and trust the recommendations.
Contribution Impact: By integrating XGBoost forecasting with seller personalization, ML-based inventory risk scoring, Agentic AI with RAG/MCP and n8n workflow execution, and profitability-focused pricing intelligence into a single platform, NexusCommerce transforms fragmented e-commerce operations into a unified, intelligent decision support ecosystem. The system's contributions span AI/ML innovation (personalized forecasting, risk scoring), software architecture (modular 3-tier stack with independent ML server), and user experience (natural language business automation with safety confirmations).

CON-4: The demand forecasting module uses XGBoost Regressor with recursive forecasting. Model accuracy depends on data quality, volume (minimum 30 days of sales history required per product), and product-specific patterns.
CON-5: The system provides recommendations and supports AI-triggered actions (such as placing supplier orders via n8n workflows), but all actions require explicit user confirmation before execution. No fully autonomous business decisions are made without user approval.
CON-6: The AI conversational assistant depends on external LLM APIs for natural language processing. The workflow automation depends on n8n webhook availability. System performance may be affected by API limits or downtime of these external services.
CON-7: Role-based access control shall be implemented. All seller_id values are extracted from JWT tokens on the server, never accepted from frontend requests, to prevent cross-seller data access.
CON-8: The system is designed for small to medium-scale datasets and is not optimized for enterprise-level scalability or high-concurrency production deployment.
CON-9: Model fine-tuning runs as a background task and may take 2-3 minutes. Only one fine-tuning job can run per seller at a time. Stuck jobs are auto-expired after 30 minutes.
CON-10: Online payments and subscription management are out of scope. The system is a decision support tool, not a transaction processing platform.

3.3 Architecture Style / Pattern
NexusCommerce adopts a Client-Server Layered Architecture combined with a Microservice-Inspired Separation of the ML processing engine. This style is chosen because it cleanly separates the system into Presentation, Service, AI/ML, and Data layers, making the platform easier to develop, test, scale, and maintain independently.
Justification for this Architecture:
The layered approach was selected because NexusCommerce integrates multiple distinct technology stacks (JavaScript/Node.js for backend, Python for ML, React for frontend) that naturally map to separate layers. The ML server runs as an independent FastAPI service on its own port (8000), allowing it to be developed, deployed, and scaled independently from the backend API server. This separation ensures that computationally intensive ML operations (model training, recursive forecasting) do not block the main API server's request handling.
Figure 12 NexusCommerce Layered Architecture Pattern Diagram
Layer Descriptions:
Presentation Layer (Next.js + React + Tailwind CSS + Recharts): Handles the user interface including dashboards with real-time filtering, forecasting visualizations with confidence bands and accuracy rings, inventory monitoring with risk badges, data management with drag-drop upload and version history, pricing analytics with profitability charts, and the AI chat interface with confirmation cards and follow-up suggestions. This layer communicates exclusively with the Service Layer through HTTPS REST API calls and never accesses the database directly.
Service Layer (Node.js + Express.js): Manages all business logic, API request handling, JWT authentication and authorization, file upload processing through Multer, data validation orchestration, and coordination between modules. This layer routes forecasting requests to the ML Layer, database operations to the Data Layer, AI queries to the external LLM API, and workflow triggers to n8n. It enforces seller isolation by extracting seller_id from JWT tokens server-side.
AI/ML Layer (Python FastAPI + XGBoost + Scikit-Learn): Runs as an independent service handling all machine learning computations. This includes XGBoost model loading with 3-tier priority (finetuned > category > fallback), recursive day-by-day prediction, temporal feature engineering (lag values, rolling means, seasonal indicators), backtest accuracy evaluation on 20% holdout data, residual standard deviation computation for confidence intervals, feature importance extraction, and background model fine-tuning with warm-start training. The ML Layer communicates directly with PostgreSQL for fetching training data and storing model metrics.
Data Layer (PostgreSQL): Stores all structured business data in a centralized relational database with 17 interconnected tables. Enforces data integrity through foreign key constraints, unique constraints for deduplication (ON CONFLICT DO NOTHING), ACID-compliant transactions for upload and rollback operations, and upsert operations for model metrics. All layers access the Data Layer through parameterized queries to prevent SQL injection.
This separation allows the frontend to stay fast and responsive while backend API handling and ML computations run independently. New modules or ML models can be added without affecting existing layers. The ML server can be scaled horizontally or moved to GPU-enabled hardware without changes to the backend or frontend.

date is parseable

price is greater than 0 if provided

Successfully inserted rows are counted as newly added records.
After all rows are processed, the system creates a new record in the upload_versions table containing the version number, rows added, rows skipped, and rows rejected.

3.4.3.3 Module 3: Inventory Intelligence & Supplier Management
Purpose: This sequence diagram illustrates the inventory monitoring and risk assessment workflow showing interactions between the System Timer/User, Backend API, ML Risk Scoring Engine, PostgreSQL Database, Supplier Service, Financial Calculator, and n8n Webhook Service.
Key Interactions:
Trigger event: new sales data uploaded OR user opens inventory module OR scheduled check.
Backend retrieves current inventory levels from inventory table.
Backend retrieves latest forecasted demand from forecasts table.
Backend retrieves supplier profiles (lead time, cost, min order) from product_suppliers table.
Backend sends product data to ML Risk Scoring Engine.
Risk Scoring Engine computes risk score per product using stock, demand, velocity, lead time.
Risk Scoring Engine assigns risk level: Critical/High/Medium/Low.
Backend stores risk scores in inventory_risk_scores table.
Backend calculates order deadlines: today + (stock / daily_demand) − lead_time.
Backend calculates restock quantities: (daily_demand × lead_time × 1.25) − stock.
